Penetration testing — এই কাজটা শুধু tool চালানো না। এটা একটা mindset।

একজন skilled pentester যখন কোনো network বা application-এর সামনে দাঁড়ায়, তখন সে চিন্তা করে একজন attacker-এর মতো — কিন্তু কাজ করে একজন defender-এর স্বার্থে। এই দুটো দৃষ্টিভঙ্গির মাঝখানে দাঁড়িয়ে থাকাটাই penetration testing-এর মূল শিল্প।

1.1 What is Penetration Testing?

Penetration Testing (সংক্ষেপে "pentest") হলো একটি authorized, simulated cyber attack — যেখানে একজন security professional একটি organization-এর systems, networks, বা applications-এ real attacker-এর মতো attack করে দেখে কোথায় দুর্বলতা আছে, সেই দুর্বলতাগুলো actually exploit করা যায় কিনা, এবং সেগুলো exploit হলে কতটুকু ক্ষতি হতে পারে।

💡
Core Concept
"আপনার security কতটা মজবুত সেটা জানতে হলে আগে নিজেই সেটাকে ভাঙার চেষ্টা করতে হবে।" — এটাই penetration testing-এর মূল দর্শন।

1.2 Benefits of Conducting Pentesting

Pentesting শুধু "compliance checkbox" নয় — এর real business value আছে:

#Benefitকীভাবে কাজ করে
1Real-world Attack SimulationActual attacker-এর মতো attack path দেখায়
2Risk Prioritizationকোন vulnerability আগে fix করতে হবে জানা যায়
3CompliancePCI DSS, ISO 27001, SOC 2 requirement পূরণ
4SOC Effectiveness TestBlue team কতক্ষণে detect করে সেটা জানা যায়
5Stakeholder AssuranceBoard, investors, clients-কে security দেখানো

৫০,০০০+ user-এর একটি platform-এ pentest-এ পাওয়া গেল: SQL Injection (পুরো DB dump সম্ভব), weak admin password, outdated payment gateway। Pentest cost: ৳৩ লক্ষ। Potential breach loss avoided: ৳৫ কোটি+। ROI: ~১৬৫৭%

1.13 When Should Pentesting Be Performed?

  • Annually — Regular security posture + Compliance (PCI DSS, ISO 27001)
  • After Major Changes — New app launch, cloud migration, merger/acquisition
  • After a Breach — কোথায় ফাঁক ছিল সেটা identify করতে
  • Before Product Launch — নতুন product বা service-এর আগে
  • Regulatory Requirement — Banking, Healthcare, Payment industry
  • Significant Code Change — Major feature addition বা architectural change

1.14 Ethics of a Penetration Tester

Technical skill থেকে ethics বেশি গুরুত্বপূর্ণ। Wrong hands-এ এই skill অত্যন্ত ক্ষতিকর।

Principleমানে
✅ Authorization FirstWritten permission ছাড়া একটি command-ও চালানো যাবে না
✅ ConfidentialityClient-এর তথ্য, findings — কিছুই third party-কে share করা যাবে না
✅ Do No HarmProduction crash, data delete, service disrupt করা যাবে না
✅ Truthful ReportingFindings minimize বা exaggerate করা — দুটোই অপ্রফেশনাল
❌ No Scope CreepScope-এর বাইরে যাওয়া যাবে না — এমনকি বড় vulnerability দেখলেও
❌ No Personal GainPentest access personal কাজে ব্যবহার করা যাবে না

Pentesting শুধু technical skill নয় — legal framework জানা equally important। Client-এর data যে jurisdiction-এ পড়ে, সেই আইন না জানলে তুমি নিজেই legal risk-এ পড়তে পারো। International client হলে multiple jurisdiction একসাথে apply হতে পারে।

2.1 Data Protection Laws in Bangladesh

বাংলাদেশে cybersecurity ও data protection-এর legal framework এখনো পরিপক্ক হচ্ছে। বর্তমানে কয়েকটি গুরুত্বপূর্ণ আইন ও বিধিমালা apply হয়:

ক) ডিজিটাল নিরাপত্তা আইন, ২০১৮ (DSA 2018)

বিষয়বিস্তারিত
পূর্ণ নামDigital Security Act, 2018
উদ্দেশ্যDigital crime প্রতিরোধ, cybersecurity নিশ্চিত করা
Pentest-এ প্রাসঙ্গিক ধারাধারা ১৭–২০: Unauthorized access, data theft, hacking
সর্বোচ্চ শাস্তি (unauthorized access)৭ বছর কারাদণ্ড বা ৳২৫ লক্ষ জরিমানা বা উভয়
Critical infrastructure attack১৪ বছর কারাদণ্ড পর্যন্ত
⚠️
Pentester-এর জন্য সতর্কতা
DSA-র ধারা ১৭ অনুযায়ী, authorization ছাড়া কোনো digital device বা system-এ access করা illegal। Written permission (engagement letter + ROE) ছাড়া pentest করলে এই আইনে মামলা হতে পারে।

খ) তথ্য ও যোগাযোগ প্রযুক্তি আইন, ২০০৬ (ICT Act)

ধারাবিষয়শাস্তি
৫৪Computer hacking৩–৭ বছর কারাদণ্ড ও জরিমানা
৫৫Computer source code damage৩ বছর পর্যন্ত কারাদণ্ড
৫৬Unauthorized system access৩–৭ বছর কারাদণ্ড
৫৭Defamatory/harmful content প্রকাশ৭–১৪ বছর কারাদণ্ড

গ) Bangladesh Bank Cybersecurity Framework

Bangladesh Bank (BB) ২০২১ সালে একটি comprehensive Cybersecurity Framework for Banks and Financial Institutions প্রকাশ করেছে। এই framework অনুযায়ী:

Requirementবিস্তারিত
Annual Pentestসকল scheduled bank-এর জন্য বার্ষিক pentest mandatory
Vulnerability AssessmentSemi-annual (বছরে দুইবার)
Pentesting FirmBB-approved বা internationally certified firm
Report SubmissionBB-তে report submit করতে হবে
Remediation DeadlineCritical findings: ৩০ দিন · High: ৯০ দিন

ঘ) Personal Data Protection Act (প্রস্তাবিত)

📌
আসছে: Bangladesh Personal Data Protection Act
বাংলাদেশ সরকার একটি Personal Data Protection Act (PDPA) প্রণয়নের প্রক্রিয়ায় রয়েছে। Draft অনুযায়ী এটি GDPR-inspired হবে এবং data subject rights, data breach notification, cross-border data transfer নিয়ন্ত্রণ করবে। Pentester হিসেবে এই আইনের update track করা জরুরি।
💡
Pentester-এর Checklist for Bangladesh Engagements
✅ Written engagement letter (বাংলা + English উভয় ভাষায় ভালো)  |  ✅ ROE-তে DSA/ICT Act reference রাখো  |  ✅ Financial sector client হলে BB framework জানো  |  ✅ Data access করলে সর্বনিম্ন access principle follow করো  |  ✅ Captured data secure handle করো, report-এ full sensitive data দেখাবে না

2.3 European Data Protection Law — GDPR

GDPR (General Data Protection Regulation) বিশ্বের সবচেয়ে comprehensive data protection law। ২০১৮ সালে effective হয়েছে। EU-র বাইরে থেকেও EU citizens-এর data process করলে GDPR apply হয়।

GDPR + Pentesting Best Practice
EU client-এর pentest করলে: (1) DPA (Data Processing Agreement) sign করো, (2) Personal data তোমার system-এ store না করার চেষ্টা করো — শুধু proof-of-concept screenshot নাও, (3) Test শেষে সব personal data securely wipe করো, (4) Report-এ personal data mask করো (e.g., user@domain.com → u***@d***.com)।

UK-Specific: Computer Misuse Act 1990 (CMA)

⚠️
UK CMA এবং Pentesting
UK-তে Computer Misuse Act 1990 unauthorized computer access criminalize করে। Section 1: Unauthorized access (6 months prison) · Section 2: Unauthorized access with intent (5 years) · Section 3: Unauthorized modification (10 years)। UK client-এর pentest করলে CMA-র explicit authorization language contract-এ থাকতে হবে।
📌
UK Pentest Industry — CREST
UK-তে CREST (Council of Registered Ethical Security Testers) হলো leading certifying body। Major UK organizations সাধারণত CREST-certified firm দিয়ে pentest করায়। UK market-এ কাজ করতে চাইলে CREST CRT (Certified Penetration Tester) certification valuable।

3.1 Pre-engagement Activities

Pre-engagement হলো pentest শুরুর আগের সব কাজ। কোনো technical কাজ এখানে নেই — কিন্তু এই phase সঠিকভাবে না করলে পুরো engagement ভেস্তে যেতে পারে।

  • RFP বা client lead receive করো — email, referral, বা direct inquiry
  • Initial NDA sign করো — আলোচনা শুরুর আগেই confidentiality নিশ্চিত করো
  • Client-কে questionnaire পাঠাও — scope বোঝার জন্য
  • Scoping call/meeting করো — scope, timeline, budget আলোচনা
  • Assessment type নির্ধারণ করো — Black/White/Grey Box
  • Testing areas identify করো — কোন systems, IPs, domains
  • Out-of-scope items define করো — কী test করা যাবে না
  • Proposal তৈরি করো — scope, timeline, cost, deliverables
  • Contract + ROE sign করো — legal protection নিশ্চিত করো
  • Kick-off call করো — সব stakeholder-কে align করো
  • Emergency contacts collect করো — testing-এর সময় কাকে call করবে
  • Lab/tools setup করো — engagement শুরুর আগেই ready করো
💡
Pro Tip — NDA আগে, কথা পরে
Client-এর infrastructure সম্পর্কে কোনো detail আলোচনার আগেই NDA sign করো। অনেক junior pentester NDA skip করে scoping শুরু করে দেয় — এটা ভুল। NDA ছাড়া sensitive information share করলে উভয়পক্ষের legal risk থাকে।

Fixed Price vs Time & Materials
Fixed Price: Scope clearly defined হলে ব্যবহার করো। Scope creep হলে তোমার ক্ষতি।  |  T&M (Time & Materials): Hourly rate × hours। Scope fuzzy হলে বা complex engagement-এ safer। Client-এর budget নিয়ন্ত্রণ কম।  |  Recommendation: Small, well-defined scope → Fixed. Large, complex, unknown → T&M।

3.8 Out-of-Scope — Tests Not to Be Performed

Out-of-scope define করা In-scope define করার মতোই গুরুত্বপূর্ণ। এটা না থাকলে তুমি কোনো system-এ test করলে পরে client বলতে পারবে "এটা তো আমি বলিনি"।

⚠️
Scope Creep — সবচেয়ে বড় বিপদ
Testing করতে করতে অনেক সময় tempting লাগে — "এই system-টা দেখি, কী হয়"। কখনো করবে না। Scope-এর বাইরে একটি IP-ও test করলে সেটা legally unauthorized access। তুমি যদি কোনো interesting system খুঁজে পাও যেটা scope-এ নেই — তা report-এ mention করো এবং client-কে জিজ্ঞেস করো scope expand করতে চায় কিনা।

3.22 Signing ROE Documents

ROE (Rules of Engagement) হলো pentest-এর সবচেয়ে important legal document। এটা scope, constraints, এবং permissions সব define করে।

ROE Document Template
=====================================
RULES OF ENGAGEMENT (ROE)
=====================================
Date:           ___________________
Client:         ___________________
Pentesting Firm:___________________
Engagement Type:___________________
Testing Period: ___ to ___

1. AUTHORIZED SYSTEMS
   The following systems are authorized for testing:
   [List of IPs, domains, applications]

2. TESTING METHODS PERMITTED
   ✅ Port scanning and enumeration
   ✅ Vulnerability scanning (non-destructive)
   ✅ Manual exploitation of identified vulnerabilities
   ✅ Privilege escalation
   ✅ Lateral movement
   ✅ Password attacks (offline cracking)
   ✅ Social engineering (if agreed)

3. TESTING METHODS PROHIBITED
   ❌ Denial of Service (DoS/DDoS)
   ❌ Destructive payloads (ransomware, wiper)
   ❌ Data exfiltration of real customer data
   ❌ Physical intrusion (unless agreed)
   ❌ Testing out-of-scope systems

4. TESTING HOURS
   Permitted:  Monday–Thursday, 09:00–18:00 BST
   Restricted: Friday–Sunday without prior approval

5. EMERGENCY STOP PROCEDURE
   If critical issue arises, pentester will:
   a) Immediately stop all testing
   b) Call emergency contact: [Phone]
   c) Send email: [Email]
   d) Document what was happening

6. DATA HANDLING
   - Captured credentials: stored encrypted, deleted post-engagement
   - PII encountered: not to be exfiltrated, to be noted only
   - Report storage: encrypted, deleted 90 days post-delivery

7. LEGAL AUTHORIZATION
   This document constitutes written authorization for the
   above-listed testing activities under:
   [Bangladesh DSA 2018 / US CFAA / UK CMA — as applicable]

8. SIGNATURES
   Client Representative: _____________ Date: _____
   Title: _____________
   
   Pentesting Lead:       _____________ Date: _____
   Title: _____________
=====================================
⚠️
ROE ছাড়া Testing = Illegal
ROE sign হওয়ার আগে একটি packet-ও পাঠাবে না target-এ। এমনকি একটি ping-ও না। ROE হলো তোমার legal shield। এটা ছাড়া তুমি criminal hacker-এর মতো same position-এ আছো।

Chapter 3 — Key Takeaways
• Pre-engagement = engagement-এর ৩০-৪০% সময় — skip করা যাবে না
• NDA → Questionnaire → Scoping Meeting → Proposal → Contract → ROE → Kick-off
• Scope clearly define করো: In-scope AND Out-of-scope উভয়
• ROE sign হওয়ার আগে একটি packet-ও পাঠাবে না
• Engagement Letter সবসময় printed copy সাথে রাখো
• Critical finding পেলে — test pause, client-কে immediately call করো
• Daily email update — client relationship maintain করার সহজ উপায়
• Timeline-এ testing + reporting উভয় সময় include করো
